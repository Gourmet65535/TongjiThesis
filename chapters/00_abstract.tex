\MakeAbstract{
    多校区办学使高校内部出行组织变得更加复杂。校区之间通勤频繁，班车、公共交通与临时拼车之间缺少统一入口，师生往往需要在不同渠道中分别检索信息、确认路线并联系同行人员。现有做法一方面增加了出行决策成本，另一方面也使拼车需求长期停留在熟人社交和临时沟通层面，难以形成稳定、可追踪的业务流程。围绕这一问题，本文设计并实现了一个基于 Spring Boot 的校内综合交通平台。系统以前后端分离方式构建，前端采用微信小程序，后端按用户、拼车、论坛、聊天、文件和交通等业务拆分服务，并结合 MySQL 与 MongoDB 形成混合存储方案。

    平台的实现重点放在拼车业务组织上。针对校园场景中路线相对固定、时间约束明确但用户选择偏好存在差异的特点，本文将拼车匹配划分为两个阶段：先依据起点、终点、日期、时间区间和剩余座位进行规则筛选，再利用随机森林模型对候选订单进行排序。模型输入综合了空间匹配、时间重叠、信用分、完成率和迟到率等特征，用于在满足基本约束的候选结果中区分优先级。除拼车功能外，系统还实现了帖子发布与评论、用户私聊、交通时刻表查询和行程反馈等功能，使信息获取、出行协同和结果反馈能够在同一平台内完成。

    测试结果表明，系统能够完成用户登录、拼车订单管理、论坛互动、即时通信和交通信息查询等主要业务流程，拼车匹配结果与场景约束基本一致，查询接口在给定并发条件下保持稳定响应。本文的工作主要面向校园交通这一具体应用场景，重点解决多源信息整合、拼车流程组织和候选排序实现问题，可为高校内部出行服务平台建设提供工程参考，也为校园共享出行场景下的数据组织与匹配方法研究提供了实例。
}{校内综合交通平台，微信小程序，Spring Boot，拼车匹配，随机森林}

\MakeAbstractEng{
    Multi-campus operation has made travel organization within universities more complex. Faculty and students often need to search for shuttle information, public transit routes, and temporary carpool opportunities from different channels, which raises the cost of travel decision-making and leaves carpooling dependent on informal social coordination. To address this problem, this paper designs and implements a campus comprehensive transportation platform based on Spring Boot. The system adopts a front-end and back-end separation architecture. A WeChat Mini Program is used as the user entry, while the back-end is divided into user, carpool, forum, chat, file, and transport services. MySQL and MongoDB are combined to support hybrid persistence.

    The implementation focuses on organizing the carpooling workflow. Considering that campus travel usually has relatively fixed routes and explicit time constraints, while user preferences still differ, the matching process is divided into two stages. Candidate orders are first filtered by origin, destination, date, time interval, and remaining seats. A random forest model is then used to rank the remaining candidates. The model considers spatial matching, time overlap, user credit, completion rate, and late rate, so that priorities can be distinguished among orders that already satisfy basic constraints. In addition to carpooling, the platform also supports post publishing and commenting, private messaging, timetable query, and trip feedback, allowing information access, travel coordination, and post-trip interaction to be completed within one system.

    Experimental results show that the platform can complete core processes including user login, carpool order management, forum interaction, instant messaging, and transport information query. The matching results are consistent with scenario constraints, and the query interfaces remain stable under the given concurrency settings. The work of this paper is oriented toward the concrete problem of campus transportation. It mainly addresses multi-source information integration, carpool workflow organization, and candidate ranking, and can provide an engineering reference for university travel service platforms.
}{Campus Comprehensive Transportation Platform, WeChat Mini Program, Spring Boot, Carpool Matching, Random Forest}
